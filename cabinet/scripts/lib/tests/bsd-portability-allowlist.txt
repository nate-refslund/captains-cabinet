# GNU-only shell primitives that are SAFE where they are.
#
# Format:  <repo-relative path> :: <rule id> :: <why it is safe here>
#
# Read by cabinet/scripts/lib/tests/test_bsd_portability.py, which fails on any
# hit that is not listed here AND on any row here that no longer matches
# anything. The second half is the one an allowlist usually forgets: without it
# the file rots into a list of things that used to be true, and a row keeps
# excusing a line somebody already fixed.
#
# A row is a claim that the primitive CANNOT bite on the macOS deployment —
# because it runs inside a Linux container, because it is a string in a policy
# fixture rather than a command, or because a capability probe or a validated
# fallback covers it. "We have not fixed it yet" is NOT one of those reasons and
# does not belong here; that is a backlog row and a red test.

The host counterpart is officer-supervisor-mac.sh, which uses no -oP.
cabinet/scripts/list-officers.sh :: date-d-unpaired :: Container-only, same evidence as the grep-P row above.
cabinet/scripts/officer-supervisor.sh :: grep-P :: Container-only — the file header says "Background loop inside the Officers container" and it reads /opt/founders-cabinet directly. officer-supervisor-mac.sh is the host counterpart and uses no -oP.
cabinet/scripts/org-health-audit.sh :: date-d-unpaired :: Container-only — CABINET_ROOT hardcoded to /opt/founders-cabinet, REDIS_HOST defaults to `redis`.

# --- stat: the leg that is only reached after the other dialect's failed ------
# `stat -f` FIRST and `stat -c` second is the order that fails silently on GNU
# (`stat -f` there means "file system" and SUCCEEDS, printing a mount point).
# The two BSD-first rows below are safe ONLY because the result is
# pattern-checked before it is used, so a GNU mount-point string is rejected
# rather than consumed. The two GNU-first rows are the correct order already.
cabinet/scripts/dashboard-password.sh :: stat-c-unpaired :: Second leg of a BSD-first chain whose result is validated by `case … ''|*[!0-7]*)` before use, so a GNU `stat -f` mount-point string cannot get through.
cabinet/scripts/egress-guard.sh :: stat-c-unpaired :: Both sites are second legs of BSD-first chains validated by `case … ''|*[!0-9]*)`.
cabinet/scripts/cabinet-doctor.sh :: stat-c-unpaired :: GNU-first `stat -c '%Y'`, with the BSD `stat -f '%m'` re-run a few lines below guarded by `if [ -z "$newest" ]`; the comment above it names this exact trap.
cabinet/scripts/runtime-provision.sh :: stat-c-unpaired :: GNU-first `stat -c '%Y %n' || stat -f '%m %N' || true`; the comment cites the measured Linux CI failure that forced this order.
