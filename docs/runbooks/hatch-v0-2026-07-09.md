# hatch.sh v0 — the one-command hatch (2026-07-09)

**What this is.** `cabinet/scripts/hatch.sh` is the THIN orchestrator of the
already-rehearsed hatch chain. It runs the exact sequence of
`docs/runbooks/mini-hatch-tonight-2026-07-07.md` (the spec of record) and
reimplements nothing — every step is an existing, proven script
(`docs/plans/world-onboarding-hatching-2026-07-09.md` §7.3: "hatch.sh
ORCHESTRATES, never reimplements"). v0 is the Terminal face; the Hatch
Cabinet.app launcher (WORLD-ONBOARDING-V1B) wraps this same engine later.

```bash
bash cabinet/scripts/hatch.sh --defaults          # the non-interactive hatch
bash cabinet/scripts/hatch.sh --dry-run --defaults  # print the plan, run nothing
```

## What v0 DOES

1. **Host bootstrap** — `setup-env.sh --defaults` (with `--defaults`) +
   `setup-mac.sh --fast` (boot-path fast lane; `--check` under `--clean-room`).
2. **Instance generation** — `generate-instance.py [--defaults]` (init
   fast-lane). An inherited `instance/` triggers the rehearsed adoption path:
   auto `--adopt` under `--defaults` (archives conflicts to
   `instance/_pre-adopt-<stamp>/`, deletes nothing), otherwise it prints the
   exact `--adopt` command and stops.
3. **Activation** (runbook step 4) — writes `instance/config/active-preset`
   from the answers' `org_shape` (the generator's own mapping: portfolio →
   portfolio, functional → work; custom = named handback), then
   `bootstrap-roles.sh --roster instance/config/roster.yml` (plain call when
   no roster.yml), then `load-preset.sh`. load-preset.sh also materializes
   `instance/config/posture.yml` + `trust-ladder.yml` from their shipped
   `.example` twins when absent (consent-safe guardian posture / floor
   ladder); an existing file or symlink is never overwritten.
4. **Proofs** (runbook step 5) — P-a `null-hatch.sh`; P-b the clean-room
   pytest subset (`test_clean_room.py`, `test_no_screenpipe_in_core.py`,
   `test_no_launcher_hardcode.py`); P-c dry renders
   (`start-officer-mac.sh cos --dry-run`, `deploy-mac.sh --officer cos
   --dry-run`); P-d kill-switch drill only with `--with-drill`. Red gate =
   stop, never proceed.
5. **FIRST RECEIPT** — `first-briefing.sh --local` (genesis contract) and
   prints where the briefing landed.
   **+ DEMO receipt** — `emit-demo-receipt.sh` seeds ONE labeled demo receipt
   (`instance/memory/demo-receipt.md`): a demo:true row built via the real
   schema path (action_undo new_row + validator) and rendered by the real
   receipt renderer — NEVER journaled, the live undo journal stays empty.
   Plan step 13; move-in renumbers to 14.
6. **Flight recorder** — per-step wall-clock timings into a flight log
   (default `~/hatch-logs/hatch-<stamp>/flight.log`, step logs beside it),
   stamps `HATCH_START` / `HATCH_PROOFS_DONE` / `FIRST_RECEIPT_DONE`, and a
   printed summary table with **TTFR** (proofs-done → first-receipt) and
   total time.
7. **Failure honesty** — a failed step prints the exact failed command + its
   log path and exits 1 (composite orchestration steps additionally print
   the underlying, paste-runnable script invocation). The one documented warn-and-continue: no
   `TELEGRAM_COS_TOKEN` name in `cabinet/.env` → the Chair boots
   Telegram-dark (rehearsal-verified) and the errand note says so.
8. **App-feel tail (Wave D, plan step 15)** — after the GREEN verdict,
   WHERE-THINGS-LIVE prints the dashboard URL
   (`http://127.0.0.1:<port>/`; port = `CABINET_DASHBOARD_PORT` env >
   `cabinet/.env` > 3100) and the Add-to-Dock/Install one-liners (Safari
   File > Add to Dock; Chrome "Install page as app"). With
   `--with-launchd` it additionally drops
   `~/Applications/Founder's Cabinet.webloc` (tmp → `plutil -lint` → mv;
   it opens the DEFAULT BROWSER — a bookmark with an app-like home, not
   an app window; true app-feel comes from the printed install lines) and
   probes `/api/health` (up to ~2 min when the port refuses; a port
   that accepts but hangs bounds at ~4 min — 60 probes × 2s curl cap +
   2s sleep) before auto-`open`ing the dashboard — auto-open is skipped
   over SSH or with `HATCH_NO_OPEN=1`,
   and a not-yet-up server prints an honest AMBER note instead.
   `--clean-room` skips the whole step (no browser, no `~/Applications`
   writes); the default `--no-launchd` run prints the
   `start-dashboard.sh` command instead of dropping a bookmark to a
   server that isn't running. NEVER a gate: the tail is wrapped so no
   failure inside it can recolor the verdict or change the exit code.

## What v0 SKIPS (deliberately)

- **launchd move-in** — default is `--no-launchd`: nothing is bootstrapped;
  the move-in commands (runbook section 6: `deploy-mac.sh --officer cos`,
  `generate-plists.py`, `plutil -lint` + `launchctl bootout || true` +
  `bootstrap` per plist — bootout-first is deploy-mac.sh's own idiom, so
  re-runs stay idempotent — then `health-check.sh`, then `cabinet-doctor.sh`
  as final acceptance) print as an errand note. `--with-launchd` runs them.
- **GERMLINE steps are NEVER automated** — the `cabinet/mcp-scope.yml` +
  `cabinet/officer-capabilities.conf` lane-CEO entries stay Captain
  copy-paste (errand note 1), exactly like BotFather tokens and TCC clicks.
- **P-d full revocation proof** — the v0 drill proves the switch flips and
  reads back; the booted-officer-refuses-tool-call proof needs a live
  officer (move-in time).
- **script(1) self-recording, native launcher, world choreography** — the
  design doc's Act I/II launcher features; v0 keeps the flight recorder only.

## Flags

| Flag | Meaning |
|---|---|
| `--defaults` | Non-interactive everywhere: `setup-env.sh --defaults`, `generate-instance.py --defaults`, auto-adopt on an inherited `instance/`. |
| `--clean-room` | Throwaway-HOME tolerant; no installs (`setup-mac.sh --check` must find deps present); never touches launchd or the live Redis (load-preset's expected-active marks point at an unused port, `HATCH_CLEANROOM_REDIS_PORT`, default 6399); DB schema apply stays load-preset's own best-effort skip; `CABINET_RUNTIME_DIR` is routed into the run's scratch area beside the flight log (`<log dir>/cabinet-runtime`; an ambient override is respected **unless it resolves to — or nests under — the live default**: a routed runtime dir *or flight-log dir* landing on `/tmp/cabinet-runtime` in any spelling — the `/private/tmp` alias, slash runs, `.`/`..` segments and symlinks are normalized before the compare — is refused, exit 64, *before anything is written*, the flight-log parent included. So a `--flight-log` directly in `/tmp` refuses — it would route the runtime dir onto the live path — as does a `--flight-log` inside `/tmp/cabinet-runtime` itself — flight.log + step logs would pollute the governance dir — and an ambient override aimed at or under the live dir: the containment must not self-defeat, adversarial fixes 2026-07-10) so the live `/tmp/cabinet-runtime/{constitution.md,safety-boundaries.md}` — the files officers read at boot — are never written (containment fix 2026-07-10, PC-B verifier follow-up (a); the routed path prints in the clean-room banner and lands in the flight log). Refuses `--with-launchd`/`--with-drill` (exit 64). |
| `--dry-run` | Print the full numbered plan + errand notes; execute nothing; exit 0. |
| `--with-launchd` | Run the move-in (runbook section 6) after the first receipt. Default: deferred errand note (`--no-launchd`). |
| `--with-drill` | Include P-d: kill-switch activate → assert ACTIVE → deactivate → assert INACTIVE against `REDIS_URL` (default `redis://localhost:6379`). Halts a live fleet by design — fresh boxes only. |
| `--flight-log <path>` | Flight log file; step logs land beside it. Ignored by `--dry-run` (nothing executes). Relative paths resolve against the repo root (warned on stderr). |
| `--help` | Usage. |

Exit codes: `0` green · `1` step failure · `64` usage/flag conflict.

## Errand notes (printed by every completed run and every `--dry-run`; human-only, numbered)

A failed run prints the failure block + flight summary instead — root-cause
and re-run; the notes return when the chain completes.

1. **Germline scope lines** — copy-paste the generator-printed lane-CEO
   entries into `cabinet/mcp-scope.yml` + `cabinet/officer-capabilities.conf`
   (fresh clones are not schg-locked; Chair-only hatch proceeds without).
2. **Chair bot token** — @BotFather → `cabinet/.env` as
   `TELEGRAM_COS_TOKEN=…` (chmod 600); `VOYAGE_API_KEY` optional
   (keyword-only degrade without it).
3. **TCC grants** — `grant-mac-permissions.sh`, only if calendar/computer-use
   is wanted; not in the base hatch.
4. **Move-in** — the launchd sequence above (omitted when `--with-launchd`
   already ran it).
5. **Healthchecks.io** — create checks per `cabinet/services.yml`
   expected-floors and ASSIGN ALERT CHANNELS; keys into `cabinet/.env`.
6. **Germline lock** — post-hatch Captain act:
   `sudo bash cabinet/scripts/germline-lock.sh lock`.
