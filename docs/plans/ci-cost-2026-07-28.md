# CI cost — measurement, cuts, and what must never move (2026-07-28)

The Actions bill got expensive. This is what it is actually spent on, measured
rather than estimated; what was cut without touching coverage; what was
deliberately *not* cut because it would have bought the saving with signal; and
an honest costing of the self-hosted-runner idea, which is the one the numbers
argue against hardest.

Standing constraint for everything below: **a cheaper CI that catches less is
not a saving.** Every line here is either provably coverage-neutral or is
recorded as a rejected trade.

---

## 1. How the numbers were taken

`billable = ceil(job_seconds / 60)`, summed per job — that is how GitHub
charges: per job, rounded up to the minute, 1× multiplier for Linux on a
private repo.

Source: the Actions REST API, every run in the 30 days to 2026-07-28 —
**765 runs, 5,026 job-runs**, per-job `started_at`/`completed_at`.

The `/actions/runs/{id}/timing` endpoint was tried first and **discarded**: it
returns `duration_ms: 0` for every job on this repo while still reporting a
plausible job count, so anything built on it would have read as a clean zero.
The per-job timestamps are the honest source.

## 3. The premise that turned out to be wrong

The brief opened on redundancy: *push and PR both fire on master, so most work
runs twice.* **Measured, that is not happening.** `push:` is scoped to
`[master, feat/fidelity-harness-design]`, and PRs come from feature branches
that are on neither list — so a PR's own commits never fire a push run. Across
the whole 30-day window, SHAs carrying both a push and a pull_request run
account for **16 billable minutes: 0.09%.**

The redundancy is real but sits one step later, and is much larger: it is the
**master push that re-tests a tree a PR run already proved green.**

---

## 4. Landed: tree-dedupe (−21% measured over 30d, −26% at the current rate)

Every merge into master here is a PR merge, and branch protection has
`strict: true` — a PR must be up to date with master before it can merge — so
the merge commit's **tree is byte-identical** to the `refs/pull/N/merge` tree
the PR run already tested. Replaying 62 minutes of gates over identical bytes
buys nothing.

Replayed over the real run history, accepting evidence only from successful
`pull_request` runs:

| window | before | skippable | after |
|---|---:|---:|---:|
| 30 days | 18,672 min | 122 runs / **3,943 min (21.1%)** | 14,729 min |
| last 7 days | 12,263 min | **3,165 min (25.8%)** | 9,098 min |
| master pushes, last 7d | 3,948 min | 88 of 103 runs — **83%** | 654 min |

A new `tree-dedupe` job resolves the pushed commit's tree and looks for a
successful PR run on the same tree; the eight gate jobs consult its verdict. It
costs one billable minute, and only on master pushes (~304/month), which is
already netted out of the figures above.

**Why this cannot become a hole** — the part that mattered more than the saving:

1. **A PR run can never be skipped.** Each gate's condition leads with
   `github.event_name != 'push'`, true for every non-push event before the
   dedupe verdict is even read. This is not belt-and-braces: GitHub reports a
   job skipped by an `if:` as **success** to branch protection, so a dedupe bug
   that reached a PR would show a green merge button over an ungated tree. The
   event guard makes that unreachable rather than unlikely.
2. **Fail-closed in every direction.** `skip` is written once, at exit, and is
   `true` only on the single path that proves a tree match. The shipping bytes
   of the step were extracted from the workflow and executed against a mock
   `gh` across nine arms — match on first/second candidate, no match, head tree
   unresolvable, candidate query failing, empty candidate list, one candidate
   unresolvable, all candidates unresolvable, `gh` broken entirely. `skip=true`
   is reachable **only** through a proven match; all eight degenerate arms
   yield `skip=false`.
3. **A failed dedupe job forces a full run, not a skipped one.** Each gate
   carries `!cancelled()`, so a red `tree-dedupe` still runs all eight.
4. **No self-certifying chain.** Evidence is accepted only from
   `pull_request` runs — a class dedupe can never have skipped — so a skipped
   (and therefore "successful") run can never become the evidence for the next
   skip.
5. **Tree, not commit.** A tree is the whole content of the checkout; two
   commits sharing one cannot make any gate answer differently. The two
   history-sensitive gates were checked individually: `gitleaks` on push scans
   the pushed range, which under `strict: true` is the same commit set the PR
   run scanned, and the nightly full-history sweep is a `schedule` run and is
   never skipped; the architecture baseline ratchet compares base→head, and its
   push base (`github.event.before`) equals the PR base for an up-to-date
   branch.
6. **A run-level `success` is stronger than the required-check set** — it means
   all eight jobs ran and passed, including `cognitive-phase4`, which branch
   protection does not require.

If `strict: true` is ever turned off, dedupe simply stops matching and the bill
goes back up. It degrades toward *more* testing, never less.

Also landed: **`feat/fidelity-harness-design` dropped from both trigger lists.**
It is 0 ahead / 894 behind master, last commit 2026-07-11. While it was live it
was a *mirror* of master — 42 SHAs in the window were pushed to both refs and
paid twice for identical work (330 min). Zero forward saving; it removes a
duplicate lane that reopens the day anyone force-pushes that ref.

## 5. Rejected: cheaper, but pays in coverage

- **Cancel superseded master runs** (`cancel-in-progress` on the master group).
  Cheap, and it would leave master commits that no gate ever ran. The current
  per-SHA group is a deliberate decision recorded in the workflow. Not touched.
- **Drop `push: [master]` and rely on PR runs.** Would take the whole 39%, and
  would leave every direct push to master — which is authorized here —
  completely ungated.
- **Path-filter docs-only changes.** Tempting and wrong in this repo
  specifically: whole-tree ratchets scan every tracked file, and the token
  guards fire on *documentation* that quotes a guarded literal. A docs-only
  commit can legitimately go red.
- **Turn off `strict: true`** to stop PR re-runs on master movement. It would
  cut PR spend, allow merging a PR never tested against current master, and
  destroy the tree-equality property dedupe depends on.
- **`cognitive-phase4` on master+nightly only** (−12 min on every PR run). It
  is not a required check, so this is easy — and it would let a PR that breaks
  the COG-4 exit gate merge and red-line master, which is the exact failure
  that job was created to stop. Dedupe already removes its master-push copy at
  no coverage cost.

## 6. The self-hosted runner on the Captain's Mac

*"Running actions on this machine is totally for free."* True of the GitHub
bill, and the total cost is elsewhere. Three findings, in order of how
expensive they are to learn the hard way.

**(a) One job would delete 82 GB of live capture state on the first run.**
`clean-room-source` executes, unsandboxed, against the runner's real `$HOME`:

```yaml
rm -rf "$HOME/.screenpipe"
mkdir -p "$HOME/.screenpipe"
: > "$HOME/.screenpipe/POISON"
chmod 000 "$HOME/.screenpipe"
```

That is correct on a disposable hosted runner and catastrophic on the Captain's
machine, where `~/.screenpipe` is 82 GB of live capture — the store the brain
index is built from. Irreversible, and it happens before any test asserts
anything. (`null-hatch.sh` is *not* exposed: it exports `HOME="$WORK/home"`
first. The composed gate is hermetic; the per-seam job relies on the runner
being throwaway.)

**(b) Three of the eight jobs cannot run there at all.**

| job | services | `apt-get` | `sudo` | writes real `$HOME` |
|---|---|---|---|---|
| `ci` | redis | yes | yes | — |
| `framework-tests` | redis, postgres | yes | — | — |
| `cognitive-phase4` | redis | yes | — | — |
| `clean-room-source` | — | — | — | **yes** |
| `clean-room-foundation`, `null-hatch`, `gitleaks`, `zizmor` | — | — | — | — |

Service containers are Linux-runner-only, and `ci`, `framework-tests` and
`cognitive-phase4` — **80% of the bill** — depend on them, on `apt-get`, and in
one case on passwordless `sudo` to symlink `/opt/founders-cabinet`. On macOS
they do not degrade, they do not run.

**(c) It is a worse environment for this suite, not a better one.** The suite
carries wall-clock assertions, and they already flake on GitHub's shared
runners: the 06:03Z scheduled run 30333546103 red-lined an unchanged commit on
a 73ms measurement against a 50ms bound, for an operation that costs ~0.2ms.
The Mac runs agent sessions, continuous screen capture, browsers and Docker.
Moving latency-sensitive gates onto it trades money for false reds — and a
false red on the enforcement plane is the most expensive signal this program
produces.

**And the integrity point, which outranks all three.** CI is the only
enforcement plane here that cannot be bypassed locally. A runner on the machine
the agents work on is reachable by the thing it is meant to police: its
workspace, its configuration, its labels and its results all sit inside the
blast radius. That does not make every job unsafe by the same amount, so, job
by job:

| job | survives a self-hosted move? | why |
|---|---|---|
| `ci`, `framework-tests`, `cognitive-phase4` | **no** | Linux services + apt; latency assertions |
| `clean-room-source`, `clean-room-foundation`, `null-hatch` | **no** | they assert *absence* of captain data; the Captain's machine is where that data lives, so the premise is destroyed even before the `rm -rf` |
| `gitleaks` | **no** | the control that stops secrets landing, moved onto the machine that holds the secrets |
| `zizmor` | **no** | polices workflow tampering; running it where workflows can be tampered with is circular |

**So: none of the eight.** Not a cost verdict — a verdict about what a gate is
for.

**If the idea is still wanted, the target is wrong, not the idea.** A dedicated
Linux host — the existing UpCloud Copenhagen box is the obvious candidate,
unverified here — restores Linux + Docker parity, carries no captain data (so
the clean-room premises survive, and nothing precious is inside `rm -rf`'s
reach), and is already paid for. It still needs: an ephemeral, per-job
registration (`--ephemeral`) so no state crosses jobs; a dedicated
non-privileged user; no ambient credentials; and the timing-sensitive jobs kept
hosted until the wall-clock bounds are measured there over at least a week.
That is a real project, not a config flag, and it should be costed before it is
started. **Recommendation: land the free 21-26% first and measure a week of the
new baseline before spending anything on runners.**

## 7. Ranked backlog, cheapest and safest first

1. **Merge the four sub-minute jobs** (`gitleaks`, `zizmor`,
   `clean-room-foundation`, `clean-room-source`) into one. They bill 4 minutes
   per run for 78 seconds of work; merged, ~2. **−2 min/run, ~3%.** Not done
   here: it renames required status checks, so it needs a branch-protection
   edit — a governance change, not an engineering one — and it costs per-job
   attribution on two security gates. Worth doing, worth the Captain's nod
   first.
2. **`Cabinet script tests`, 1,087s — 32% of a full run's wall clock in one
   step.** The biggest honest target left, and the workflow's own timeout note
   already names splitting it as the fix it is waiting for. Profiled here
   (5,021 passed / 34 skipped, 811s serial locally): it is **long tail, not a
   hot spot** — the slowest 30 tests are ~350s of 811s, and the top single item
   is 97s (`test_egg_export.py::test_cognitive_architecture_verifier_runs_inside_export`).
   That shape is what `-n auto` is for, and on a 4-core runner it is plausibly
   worth ~10 min/run — but this directory holds the killswitch, safety-switch
   and freeze fences, which is exactly the code that must not be raced.
   Splitting it into a second **serial** job would buy wall-clock latency and
   nothing on the bill (two jobs still bill the same minutes plus a rounding
   floor). So the honest sequence is: prove which tests are order- and
   timing-independent, parallelise only those, keep the fences serial. Real
   work, not a flag.
3. **`ci`'s vitest step, 34s → 5m43 in three weeks.** Real work arriving (world
   capture pixel gate), so this is a watch item, not a cut. It is the fastest-
   growing line in the bill.
4. **A dedicated Linux self-hosted runner**, per §6 — costed, not started.
