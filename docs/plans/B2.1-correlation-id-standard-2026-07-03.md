# B2.1 — Correlation-ID Propagation Standard (2026-07-03)

> **Status:** shipped (helper + wire + tests). The join key the outcome-probe fleet
> (B2.3–B2.7) and the capture→action executor stamp and read back. Plan-B §B2.1.

## Why

An outcome probe observes an **external artifact** — a Vercel deploy, a Sentry
release, a git commit, a support thread — and must join it back to the Cabinet
**proposal** that caused it. Joining on time/author is forbidden (RT#3: it
manufactures false evidence). The join is an explicit id, minted at proposal time
and carried *into* the artifact.

Two distinct correlation keys, do not conflate:

| key | what | where | used by |
|---|---|---|---|
| **proposal_id** (identity tuple `actor\|action\|subject\|ts`) | internal binding of a Captain reply to its pending proposal | the ledger event | the binder / `reply_binder` |
| **correlation-id** (uuid4) — *this standard* | external join of an artifact to its proposal | `refs[]` on the event + stamped in the artifact | the probes / executor |

## The standard (single source of truth: `framework/probes/correlation.py`)

- **Mint:** `correlation.mint()` → uuid4 hex (32). Minted in `loop.propose()` if
  the proposal carries no id yet (mint-if-absent; injectable for tests). Additive
  to `refs` — `proposal_id` is unchanged, so the binder/pending logic is untouched.
- **Carry on the event:** `refs[]` holds `cabinet-proposal-id:<uuid>`
  (`ref_for` / `cid_from_refs`). No schema change — `refs` is already a validated
  array of strings.

### Propagation formats (stamped by downstream execution)

| Artifact | Format | Stamper | Read-back |
|---|---|---|---|
| Git commit / PR | trailer `Cabinet-Proposal-Id: <uuid>` in the final paragraph | `git_trailer` | `from_git_trailer` / `extract` |
| Vercel deploy | `--meta cabinetProposalId=<uuid>` | `vercel_meta` | probe reads `meta.cabinetProposalId` |
| Sentry | `release = <commit-sha>` (standard) → resolve via the commit trailer | — | trailer read-back off the release SHA |
| Support email (Resend) | header `X-Cabinet-Proposal-Id: <uuid>` + subject `[CAB-<short8>]` | `resend_header` / `subject_tag` | header dict / `from_subject_tag` |
| Monday update | body footer `cabinet-proposal-id: <uuid>` | `monday_footer` | `extract` |

Extractors are **strict, prefix-anchored**, and reject a 32-hex *prefix* of a
longer blob (`(?![0-9a-f])`) so untrusted artifact text can't smuggle a false id
into the join.

## The join model

```
proposal (refs: cabinet-proposal-id:X)  ──mint──▶  execution stamps X into the artifact
                                                          │
probe observes artifact ──extract X──▶ match to the proposal whose refs carry X ──▶ outcome event
```

## Rules (RT#3 — no manufactured evidence)

- **Never infer** the proposal from time/author heuristics. The id is present or
  the artifact is unattributable.
- **Unattributable artifacts** (human merges, external pushes, id-less deploys)
  record `outcome.status = unknown` and **credit no officer** — they neither
  climb nor sink any graduation cell.
- **F0.6 (junk-event kill) must be green** before any probe loads — polluted
  completions must never enter the join.

## Downstream wiring (B2.3–B2.7 + executor build on this)

- A `commit-msg` git hook (`cabinet/scripts/git-hooks/commit-msg-cabinet`,
  installed per product-repo clone) auto-appends `git_trailer(active-cid)` and
  refuses officer commits without one; the pre-tool-use hook backstops.
- The executor stamps the id at the moment it produces each artifact (deploy meta,
  email header, Monday footer) using the stampers above — never re-derives a format.
- Each probe extracts and emits a schema-valid, confidence-tagged outcome event
  through `probes/lib.py` (lands with B2.2, the probe framework).

## What shipped now vs. next

- **Now:** the `correlation` standard (mint/stamp/extract) + `loop.propose()`
  mint-if-absent wire + 12 tests.
- **Next (B2.2):** `probes/lib.py` — the schema-valid emit/confidence/freshness
  harness every probe shares. Then the fleet (B2.3–B2.7) fans out — each probe
  independent, all joining on this id.
